After the interview I pretty quickly spot checked that a new PlayBackVC was being created in memory every time when we present the VC after a call tap. That's likely the reason for the application memory pressure we were observing and the PlayBackVC still being in memory. To fix this I'd simply have the SearchVC create a PlayBackVC once and retain it in memory as a strongly referenced property. We could then re-present this single created VC instance every time on cell tap, which should prevent the memory spikes and unnecessary allocations. The VC may need to be refactored to accept a settable data/view model for things like the playback URL, but thats easy to do.
